왜 그랬을까 — 원인과 결과 놀이터

아이가 친구 사이의 다툼과 오해를 두 관점(A/B)에서 다시 보며, "왜 그런 일이 일어났고, 그래서 어떻게 되었는지"를 스스로 연결하도록 돕는 상황극 게임 기획서입니다.

01배경 및 문제 정의

아이에게 친구 관계 속 갈등 상황을 보여주고, 그 원인과 결과를 이해시키는 놀이 콘텐츠를 만든다. 상황 그림이 제시되면 ① 상황을 설명하고, ② A 친구의 관점에서 왜 그랬는지·감정이 어땠는지·그래서 어떻게 되었는지를 보여주고, ③ 같은 방식으로 B 친구의 관점도 보여준다.

계기가 된 실제 상황

기존에 운영 중인 게임·서비스에서 발생한 버그가 아니라, 실생활에서 아이에게 "왜 때렸어?"라고 물었더니 "머리가 아파서요"처럼 상황과 무관한 대답이 돌아온 경험이 출발점이다. 아이는 원인을 그림/사건과 연결해 설명하는 연습이 되어 있지 않았다 — 이 게임은 그 연습을 시켜주기 위한 새 콘텐츠다.

이 문서는 이 문제를 구조적으로 막기 위한 콘텐츠 설계 원칙과 응답 로직, 그리고 상황 초안을 포함한 기획서다.

v0.2 변경 사항

「원인결과 상황예시.md」에 정리된 35개 상황 초안, 8단계 게임 엔진 구조, "가능한 이유" 복수 제시 방식, 5가지 핵심 유형 우선순위를 반영해 04·05·06·07·08장을 갱신했다.

02목표

학습 목표 — 5가지 핵심 유형

낱개 상황 30~35개를 외우게 하는 것이 목표가 아니다. 아래 5가지 경험을 여러 상황에서 반복시키는 것이 진짜 목표이며, 07장의 콘텐츠는 이 5가지를 담는 그릇이다.

  1. 내가 하고 싶은 것 vs 친구가 하고 싶은 것 — "나는 하고 싶지만 친구는 싫을 수 있어."
  2. 원인과 결과의 연결 — 내 행동 → 친구의 감정 → 친구의 행동 → 나의 결과로 이어짐을 본다.
  3. 거절 받아들이기 — "싫어"를 들었을 때의 내 감정과, 그다음 내가 고를 수 있는 다른 행동.
  4. 충동 조절 — "하고 싶다"는 마음이 들어도 멈추고, 생각하고, 행동을 선택할 수 있다.
  5. A/B 두 관점으로 보기 (가장 중요) — "누가 맞아?"가 아니라 "A는 왜 그랬을까? B는 왜 그랬을까?"를 묻는다.

제품 목표

  • 상황–원인–감정–행동–결과가 항상 논리적으로 연결된 콘텐츠를 제작·검증한다(1차 30~35개).
  • 아이가 캐릭터에게 자유롭게 질문해도, 답변이 상황 설정을 벗어나지 않도록(그라운딩) 보장한다.
  • 원인을 하나로 단정하기보다 "가능한 이유" 2~3개를 함께 보여줘, 정답 맞히기가 아닌 추론 연습이 되게 한다.

03대상 사용자 및 가정

  • 주 사용자: 만 5~8세, 스스로 글을 읽을 수 있는 아동 — 내레이션 음성 없이 텍스트만으로 진행 가능
  • 보조 사용자: 대부분 보호자가 함께 지켜보며 아이의 자유 발화(대답)를 듣거나 대신 입력해줌
  • 플랫폼: 웹(브라우저)에 게시 — 별도 앱 설치 없이 링크로 접근
  • 사용 맥락: 짧은 세션(상황 1개당 1~2분, 1회 3~5개 상황)

04핵심 개념 & 게임 루프

모든 상황은 동일한 8단계 루프를 따른다. 게임 엔진 자체를 이 구조로 고정하고, 콘텐츠(07장)만 갈아 끼운다.

①무슨 일이 일어났어?상황 그림 + 내레이션
→
②A는 왜 그랬을까?가능한 이유 2~3개 중 추측
→
③A는 어떤 기분일까?감정 카드 공개
→
④A에게 무슨 일이?결과 공개
→
⑤B는 왜 그랬을까?가능한 이유 2~3개 중 추측
→
⑥B는 어떤 기분일까?감정 카드 공개
→
⑦B에게 무슨 일이?결과 공개
→
⑧다음엔 어떻게?대안 행동 제안

자유 발화 → "이런 생각도 있어요" 예시 제시

②·⑤·⑧ 단계는 객관식이 아니라 먼저 아이가 자유롭게 대답(직접 타이핑하거나 보호자가 대신 입력)하게 한다. 답을 제출하면 그제서야 "이렇게 생각한 친구들도 있어요" 형태로 그럴듯한 예시 2~3개를 보여준다 — 아이의 답을 채점하기 위해서가 아니라, 다르게도 생각해볼 수 있음을 넓혀주기 위해서다.

예시 — "A가 B를 밀었어. 왜 그랬을까?" (아이 입력 후 공개)
장난으로 빨리 가고 싶어서 화가 나서

아이가 무엇을 답했든 부정하지 않는다. 이 예시들 중 실제 상황의 원인 하나만 이후 ③·④(또는 ⑥·⑦) 감정·결과 카드와 일치하도록 저작한다.

예시 — "친구를 때렸어요"

하늘과 바다가 나오는 예시. 이름·그림은 제작 시 상황마다 다양화한다.

하늘의 마음 (때린 아이)
원인
바다가 내가 쌓던 블록탑을 발로 차서 무너뜨렸다.
감정
속상함 → 화남
행동
화가 나서 바다를 손으로 때렸다.
결과
선생님께 혼났고, 바다가 우는 걸 보고 미안해졌다.
바다의 마음 (맞은 아이)
원인
급하게 지나가다 발이 블록탑에 걸려 넘어뜨렸다(고의 아님).
감정
당황함 → 놀람과 아픔
행동
미안하다고 말할 새도 없이 하늘에게 맞았다.
결과
손등이 아팠고, 왜 맞았는지 몰라 억울했다가 하늘의 사과를 듣고 풀렸다.

같은 사건이지만 하늘은 "고의로 무너뜨렸다"고 느꼈고, 바다는 "실수였다"고 느꼈다 — 이 인식 차이가 갈등의 진짜 원인이며, 아이가 이해해야 할 핵심이다.

05콘텐츠 설계 원칙

"머리가 아파서요" 같은 문제를 재발시키지 않기 위한 저작 규칙이다. 모든 상황은 아래 6가지를 통과해야 콘텐츠로 등록할 수 있다.

  1. 원인은 그림 속 사건을 구체적으로 지칭해야 한다. "화가 나서" 같은 감정 단어만으로는 원인이 될 수 없다.
  2. 신체 상태(배고픔·머리 아픔 등)는 단독 원인으로 금지한다. 배경 요인으로는 허용하되, 반드시 상황 속 사건과 함께 제시한다.
  3. 원인 → 감정 → 행동 → 결과 4단계가 모두 채워져야 하며, 감정이 원인과 행동을 논리적으로 이어야 한다.
  4. A와 B의 원인은 서로 달라도 된다. 오히려 서로 다른 사실을 봤기 때문에 갈등이 생겼다는 설정을 우선한다.
  5. 결과는 행동의 직접적 여파(다침, 혼남, 미안함, 화해 등)여야 하며 상황과 무관한 결말은 금지한다.
  6. 문장은 짧게(1~2개 절, 8~12어절 이내) 쓰고, "나쁜 아이/착한 아이" 식 이분법 표현은 쓰지 않는다.
  7. 원인은 하나로 단정하지 않는다. 아이의 자유 응답을 먼저 받고, 04장처럼 "이렇게 생각한 친구들도 있어요" 예시 2~3개를 나중에 보여준다. 이 예시 중 하나만 실제 원인과 일치하면 되고, 나머지도 그 상황에서 있을 법한 이유여야 한다(터무니없는 오답 금지). 아이의 답은 채점하지 않는다.

콘텐츠 우선순위 — 02장 5가지 핵심 유형

07장의 35개 초안은 완결된 최종 목록이 아니라 5가지 핵심 유형을 반복 경험시키기 위한 재료다. 콘텐츠를 늘리거나 줄일 때는 개수보다 아래 배분을 기준으로 판단한다.

Tier대응하는 핵심 유형
Tier 1② 원인과 결과의 연결 — A/B 모두 원인→감정→행동→결과 완전한 사슬로 학습
Tier 2① 나 vs 친구 · ③ 거절 받아들이기 — 감정·관점 차이 자체에 집중
Tier 3④ 충동 조절 — "하고 싶다 → 멈춤 → 선택"의 훈련
Tier 4⑤ A/B 두 관점으로 보기(심화) — 해석 차이·사과·협의 등 복합 추론

나쁜 예 vs 좋은 예

기존 (문제)
Q. "왜 때렸어?"
"머리가 아파서요."
원인이 상황(블록탑)과 무관하고, 감정·행동과도 연결되지 않는다. 아이가 인과관계를 배울 수 없다.
개선
Q. "왜 때렸어?"
"바다가 내 블록탑을 발로 차서, 속상하고 화가 나서 그랬어요."
그림 속 사건(블록탑이 무너짐) → 감정(속상함·화남) → 행동(때림)이 한 문장 안에서 연결된다.

07상황 35선 (초안)

「원인결과 상황예시.md」의 초안을 4개 Tier로 반영했다. 뒤로 갈수록 원인 추론이 복잡해진다 — Tier 1은 A/B 모두 원인→감정→행동→결과를 완전히 채운 기본형이고, Tier 2~4는 핵심 포인트만 잡은 개념 초안이라 15장 오픈 이슈에서 다시 언급하듯 제작 전 06장 스키마에 맞춰 보강이 필요하다.

Tier 1 기본 원인·결과 이해

A/B 각각 원인 → 감정 → 행동 → 결과 4단계가 모두 드러나는, 08장 루프의 정석형 상황.

#상황A (원인→감정→행동→결과)B (원인→감정→행동→결과)
01A가 B의 장난감을 가져감장난감이 갖고 싶었다 → 기대됨 → 가져감 → 장난감을 가짐장난감을 갖고 놀고 있었다 → 당황/속상 → 빼앗김 → 놀이가 중단됨
02A가 B에게 공을 던짐공을 같이 던지고 싶음 → 신남 → 던짐 → B가 맞음공을 보고 있음 → 놀람/아픔 → 맞음 → 놀이가 중단됨
03A가 B를 밀어서 먼저 줄에 섬빨리 하고 싶음 → 조급함 → 밀음 → 먼저 섬차례를 기다림 → 놀람/화남 → 밀림 → 차례를 빼앗김
04A가 B의 그림 위에 그림을 그림같이 그리고 싶음 → 재밌을 것 같음 → 그림 그림 → B 그림이 바뀜열심히 그림 → 당황/속상 → 그림이 망가짐
05A가 B에게 사탕을 하나 줌B에게 주고 싶음 → 기분 좋음 → 줌 → B가 받음사탕을 보고 있음 → 기쁨 → 받음 → 함께 먹음
06A가 물을 쏟음물을 마시려 함 → 실수함 → 쏟음 → 바닥이 젖음옆에 있음 → 놀람 → 물에 젖음 → 닦아야 함
07A가 블록을 무너뜨림재밌게 놀고 싶음 → 신남 → 블록을 건드림 → 탑이 무너짐열심히 쌓음 → 놀람/속상 → 탑이 무너짐
08A와 B가 같은 장난감을 동시에 잡음갖고 싶음 → 아쉬움 → 잡음 → 서로 당김갖고 싶음 → 아쉬움 → 잡음 → 서로 당김

Tier 2 감정과 관점 연결

사건 자체보다 "같은 순간을 A와 B가 다르게 느낀다"는 관점 차이에 집중한 상황 — 학습 목표 ①·③(01장)과 직결된다.

#상황핵심
09A가 "같이 놀자"고 했는데 B가 "싫어"라고 함A: 거절당해 실망 / B: 혼자 놀고 싶었음
10A가 같이 놀자고 했는데 B가 다른 친구와 놀러 감A: 서운함 / B: 다른 친구와 놀고 싶었음
11A가 B에게 장난을 쳤는데 B가 화냄A: 재밌다고 생각 / B: 불편하고 싫음
12A가 B를 안아주려고 했는데 B가 피함A: 친해지고 싶음 / B: 안기기 싫음
13A가 B의 손을 잡았는데 B가 손을 뺌A: 같이 가고 싶음 / B: 혼자 가고 싶음
14A가 계속 말을 걸지만 B는 다른 곳을 봄A: 이야기하고 싶음 / B: 지금은 집중하고 싶음
15A가 B의 모자를 써봄A: 재밌을 것 같음 / B: 허락 없이 써서 싫음
16A가 B의 간식을 보고 "나도 줘"라고 함A: 먹고 싶음 / B: 자기 간식을 지키고 싶음
17A가 B에게 "너 못해"라고 말함A: 자신이 더 잘한다고 생각 / B: 속상하고 자신감이 떨어짐
18A가 게임에서 이기고 크게 소리 지름A: 너무 기쁨 / B: 속상하거나 시끄러워서 불편

Tier 3 충동 억제 + 사회적 규칙

"하고 싶다 → 멈춤 → 생각 → 행동 선택"의 흐름을 다루는 상황 — 학습 목표 ④(01장)와 직결된다.

#상황핵심
19A가 줄을 서 있는데 앞 친구를 추월함하고 싶은 마음 → 참기 → 차례 기다리기
20A가 친구가 만든 블록을 보고 만지고 싶어 함충동 → 허락 요청 → 결과
21A가 친구의 장난감을 보고 바로 가져가려 함갖고 싶음 ≠ 바로 가져도 됨
22A가 친구가 말하는 중 끼어듦하고 싶은 말이 떠오름 → 기다리기 어려움 → 끼어듦
23A가 수업 중 갑자기 소리를 지름재밌거나 답답함 → 충동 → 소리 냄 → 친구들이 놀람
24A가 친구가 낮잠 자는 동안 장난감을 가지고 놂심심함 → 놀고 싶음 → 놀이 → 친구의 잠을 방해
25A가 친구의 몸을 계속 만지거나 찌름관심/장난치고 싶음 → 손이 먼저 움직임 → B가 불편함
26A가 친구에게 계속 가까이 다가감친해지고 싶음 → 거리 조절 어려움 → B가 뒤로 물러남

Tier 4 복잡한 원인 추론

해석 차이·연쇄 반응·사과와 협의처럼 원인이 한 번에 드러나지 않는 심화 상황 — 학습 목표 ⑤(01장)의 확장판.

#상황핵심
27A가 B의 블록을 무너뜨리고 B가 A를 밀침행동 → 감정 → 반응 → 새로운 결과(연쇄)
28A가 B에게 공을 던졌는데 B가 돌려주지 않음A의 의도와 B의 해석이 다를 수 있음
29A가 B를 보고 웃었는데 B가 화냄A는 장난 / B는 놀림으로 해석
30A가 B의 그림을 보고 "이상해"라고 말함A의 생각 표현 → B의 감정 → 관계 변화
31A가 "같이 하자"고 했지만 B가 "나중에"라고 함거절이 아니라 잠시 미루는 상황
32A가 실수로 B의 작품을 밟음고의가 아님 → B의 감정 → A의 사과/도움
33A가 먼저 사과했는데 B가 바로 받아주지 않음사과했다고 상대가 즉시 괜찮아지는 것은 아님
34A와 B가 서로 다른 규칙으로 게임을 하려고 함각자의 생각 → 갈등 → 협의
35A가 "내가 이거 빌려줄게" 했는데 B가 거절함A의 호의 → B의 선택 → 거절을 받아들이기

Tier 분포 — Tier 1(기본형) 8개 · Tier 2(관점) 10개 · Tier 3(충동 조절) 8개 · Tier 4(심화 추론) 9개. 제작 착수 전 아동 발달 전문가 검수를 거쳐 최종 반영 개수와 순번을 확정한다.

08화면·상호작용 흐름

단계화면아이의 행동비고
①상황 삽화 + 내레이션 ("무슨 일이 일어났어?")보고 듣기효과음 포함, 3초 이상 노출 후 다음 진행 가능
②"A는 왜 그랬을까?"자유 응답 입력 → 제출 후 예시 2~3개 확인정답 채점 없음, 예시는 exampleReasons 사용
③"A는 어떤 기분일까?"감정 카드 탭하여 열람감정은 표정 아이콘 병기, ②에서 낸 생각과 자연스럽게 연결
④"그래서 A에게 무슨 일이?"결과 카드 열람A 계열 색(코랄)으로 통일
⑤"B는 왜 그랬을까?"자유 응답 입력 → 제출 후 예시 2~3개 확인A와 다른 사실을 보고 있었을 수 있음을 강조
⑥"B는 어떤 기분일까?"감정 카드 열람B 계열 색(블루)으로 통일해 A와 시각적으로 구분
⑦"그래서 B에게 무슨 일이?"결과 카드 열람"둘 다 이유가 있었어요" 톤 유지, 승패 판정 없음
⑧"다음엔 어떻게 하면 좋을까?"자유 응답 입력 → 제출 후 대안 예시 확인resolutionTip/exampleReasons 필드 사용

09캐릭터 대화 응답 로직 (그라운딩)

이 장은 "머리가 아파서요" 문제의 기술적 원인을 막기 위한 필수 요구사항이다.

  • 자유 생성 금지: 아이가 캐릭터에게 무엇을 묻든, 답변은 해당 상황의 perspectiveA/B.trigger와 emotion 필드에서만 근거를 가져온다. LLM이 상황과 무관한 내용을 새로 지어내지 않도록 답변 생성 시 해당 필드를 컨텍스트로 강제 주입한다.
  • 저작 시점 QA: 상황마다 최소 3개 예상 질문 — "왜 그랬어?", "기분이 어땠어?", "그래서 어떻게 됐어?" — 에 대한 답이 followUpQA에 미리 채워져 있어야 릴리스 가능. 빈 항목이 있으면 배포 차단.
  • 범위 밖 질문 처리: 스키마에 없는 질문(예: "머리 아파?")이 들어오면 사실과 무관한 답을 지어내는 대신, 상황으로 되돌리는 정해진 응답을 쓴다 — 예) "그건 잘 모르겠어. 근데 그때 마음이 좀 화가 났어. 왜 그랬는지 같이 볼까?"
  • 회귀 테스트: 릴리스 전 전체 상황에 대해 "왜 그랬어?" 질문을 자동 실행해, 답변에 trigger 필드의 핵심 명사(예: "블록탑")가 포함되는지 검사한다.
  • 예시 답변도 그라운딩 대상: 04장의 exampleReasons는 무작위 생성이 아니라 저작 시점에 상황별로 미리 채워둔다. 이 중 하나는 실제 trigger·감정·결과 카드와 일치해야 하며, 나머지도 그 상황에서 있을 법한 이유여야 한다(05장 원칙 7). 아이의 자유 응답 자체는 저장·평가하지 않는다.

10학습 효과 확인 방법

  • 사전 예측 vs 사후 비교: 2단계에서 아이가 고른 예측과 실제 A/B 원인을 비교해 "너도 비슷하게 생각했구나" 식 피드백 제공(정답/오답 채점 아님).
  • 미니 회고 퀴즈: 5개 상황마다 "그때 하늘이는 왜 화났을까?" 객관식 1문항으로 원인-결과 기억을 확인.
  • 보호자 리포트(선택): 이번 주 다룬 감정 단어·상황 카테고리를 요약해 보호자에게 보여줘 실생활 대화로 이어지게 함.

11비기능 요구사항

  • 언어 수준: 문장 8~12어절, 초등 1학년 국어 교과 수준 어휘 사용.
  • 플랫폼: 웹 브라우저(반응형, 모바일/태블릿/데스크톱), 별도 설치 없이 링크로 접근.
  • 오디오: 내레이션 음성은 필수가 아니다(아이가 스스로 읽을 수 있음을 가정). 대신 상황이 바뀔 때와 단계(①~⑧)가 바뀔 때 서로 다른 짧은 효과음을 재생해 전환을 인지시킨다.
  • 그림 스타일: 감정 표현이 과장 없이 분명한 일러스트(표정 위주), 폭력적 묘사(때리는 순간의 타격 이펙트 등) 최소화.
  • 접근성: 큰 탭 영역(44px 이상), 색맹 고려해 A/B 구분에 색+아이콘 병기.

15오픈 이슈 · 확인 필요 사항

해결된 사항 (v0.2 논의 반영)

  • ②·⑤·⑧ 입력 방식: 선택지 먼저가 아니라 자유 응답 → 제출 후 예시 2~3개 공개로 확정 (04·05·06·08장 반영).
  • 플랫폼: 웹 게시로 확정. 기존에 이 문제를 겪은 별도 시스템은 없으며, "왜 때렸어?" 사례는 실생활에서 관찰된 계기일 뿐 이 게임이 첫 구현이다.
  • 캐릭터 구성: 상황마다 다른 캐릭터일 필요는 없지만, 동일한 두 캐릭터(예: 하늘·바다)를 전 상황에 반복 등장시키는 것은 지양 — 몇 개의 캐릭터 세트를 돌려쓰는 방식으로 확정.
  • 오디오: 내레이션 음성 없이 텍스트로 진행(아이가 읽을 수 있음, 보호자 대부분 동석). 대신 상황 전환음·단계 전환음 2종을 구분해 재생.

남은 오픈 이슈

  • Tier 2~4 상세화: 09~35번 상황은 현재 원인·감정 위주의 개념 초안이라 행동(action)·결과(result)·예시 답변(exampleReasons)이 비어 있다. 06장 스키마 기준으로 전부 채워야 제작에 들어갈 수 있다. 우선 Tier 1의 3개 상황(01~03)을 선작업한 프로토타입으로 엔진을 검증한 뒤 나머지를 순차적으로 채워 넣는다.
  • 35개 유지 여부: 원안이 35개로, 애초 목표였던 "약 30개"를 넘어선다. 전부 제작할지, 05장의 Tier별 우선순위에 따라 1차 릴리스 범위를 줄일지 결정 필요.
